## 3. THE ONE THING TO FIX FIRST — do the test before touching anything

**Camera frames carry timestamps ~4.3 s older than the laser's**, measured
from the same Pi over the same link (laser 178 ms, RGB 4300 ms, stable
across six 10 s buckets). Fix #47 looks up the robot's pose *at the frame's
stamp*, so while the robot moves it uses a 4.3 s-old pose, projects the
object to the wrong map position, exceeds `GOAL_REISSUE` (0.9 m), and
cancels and re-sends the Nav2 goal — which per the agent's own #58 comment
IS the jerky stop-start motion. Stationary, the bug is invisible.
Related: `SCAN_DWELL_S = 3.5 s` is SHORTER than the lag, so the "stare"
half of step-and-stare never sees a stationary frame.

Operator, first-hand: *"the frames arrive late and sometimes are not
received by the agent."*

### THE DISCRIMINATING TEST — free, do it right after undocking

Two candidate causes need **opposite** fixes, so do not guess:

1. Undock. The camera restarts by itself.
2. Immediately run `python3 ~/vla_tools/oakd_rgbd.py`, then
   `python3 ~/vla_tools/latency_probe.py`, then again after 10 minutes.

* **offset near zero at first, growing** -> the driver's clock conversion is
  drifting. Fix: re-stamp frames on arrival (agent change -> flag + diff
  first), or restart the camera periodically.
* **~4.3 s immediately, not growing** -> genuine buffering. Fix on the ROBOT,
  no shared file: lower `rgb.i_fps` (30) and `rgb.i_max_q_size` (10) as
  runtime parameters the same way `oakd_rgbd.py` sets the pipeline type.
  Try `i_fps: 10`, `i_max_q_size: 1`, then re-measure.

Only after this is settled should the agent be considered for a change, and
then only behind a flag, with the diff shown to the user first.

## 6. TRAPS — 8 Sep's still apply; these are NEW on 10 Sep

**6.1 `vla-box` has no `xterm`.** An `xterm -e` launcher there opens nothing
and fails silently. Use `nohup` + a log file.

**6.2 `vla_kill.sh` does not stop `yolo_server`.** Not in its group-kill
patterns nor its orphan sweep. Kill by PID, in a separate command.

**6.3 A SHORT `ros2 node list` is not proof of death.** While docked it
omitted `turtlebot4_node` and `create3_repub` while those very nodes were
publishing `dock_status` and `battery_state` in the same minute. Confirm
with `topic hz` / `topic echo` before concluding anything is dead.

**6.4 The Dock action can ABORT.** `redock.py`'s Nav2 leg succeeded in 12 s;
the Dock action then ran 79 s and returned `status=6 ABORTED,
is_docked=False`, leaving the robot off the charger. **Watch it finish and
verify `is_docked: true` AND `current > 0`.** Have the user dock by hand if
it fails.

**6.5 A manual move invalidates SLAM.** Lifting the robot onto the dock
leaves `map -> odom` wrong, because odometry saw nothing. Restart SLAM (or
set a 2D Pose Estimate) before navigating.

**6.6 The PC is not NTP-synced.** Do not trust absolute PC-vs-Pi timestamp
differences. Use `/robot1/scan` (178 ms) as the baseline and compare other
Pi-sourced streams to it; the common offset cancels.

**6.7 Nav2 wobbles into unexplored space.** A 1.9 m goal on a nearly empty
costmap took 75 s and retreated from 0.22 m to 0.91 m before succeeding.
Build some map first.

**6.8 The RGBD switch is not persistent.** Reverts on Pi reboot or
`turtlebot4.service` restart. Re-run `oakd_rgbd.py` every session (§4 step 7).
